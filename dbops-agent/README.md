# DBOps Agent — AI Database Incident Investigator

A read-only database incident investigation agent built for **Amazon Bedrock Managed Agents on AgentCore Runtime**.

The first implementation focuses on Amazon OpenSearch Service + CloudWatch. The agent uses reusable Codex skills to investigate alerts, gather evidence, correlate signals, and produce an RCA. It does **not** mutate production resources.

## Current implementation

- AgentCore Runtime project bootstrap compatible with the current `BedrockManagedAgents` flow
- OpenSearch diagnostics: cluster health, nodes, JVM, thread pools, shards, indices
- CloudWatch metric/log diagnostics
- Evidence collection and JSON incident report generation
- Guardrails for read-only operation
- Session-aware client based on the current AWS OpenAI-compatible Bedrock Managed Agents API
- Unit tests for diagnostic parsing/report generation
- Optional VPC deployment parameters

AWS currently documents Bedrock Managed Agents with OpenAI on AgentCore Runtime as preview. The current AWS flow uses `agentcore create --framework BedrockManagedAgents`, a Runtime container running `codex exec-server`, `/opt/bma/plugins` for skills, and a separate session role. See the AWS documentation before deployment because preview APIs may change.

## 1. Prerequisites

- Node.js 20+
- AWS CLI credentials
- `uv`
- Docker only if your local workflow requires it; AWS AgentCore CLI builds the image with CodeBuild
- AWS account with access to Bedrock Managed Agents and the required AgentCore permissions
- Model access for `openai.gpt-5.6-luna` in the target Region

Install the current AgentCore CLI:

```bash
npm install -g @aws/agentcore
agentcore --version
```

## 2. Bootstrap the AWS-generated Runtime scaffold

The AWS documentation explicitly says the lifecycle server is generated by the AgentCore CLI and should not be modified. This repository therefore does not invent that implementation.

Run:

```bash
./scripts/bootstrap_from_aws.sh
```

The script runs the current AWS CLI generator in a temporary directory and copies the generated `lifecycle/server.py`, generated Docker/observability scaffolding, and `agentcore/` files into this repository while preserving the DBOps implementation.

For VPC deployment, export:

```bash
export AWS_REGION=us-east-1
export VPC_ID=vpc-xxxxxxxx
export SUBNET_IDS=subnet-aaa,subnet-bbb
export SECURITY_GROUP_IDS=sg-xxxxxxxx
```

Then run the bootstrap script. The VPC must have a route to the Bedrock Managed Agents endpoint and the image build needs internet access as described by AWS.

## 3. Configure OpenSearch

For the POC, use a managed Amazon OpenSearch Service domain with IAM/SigV4 access.

```bash
export OPENSEARCH_ENDPOINT=https://search-example-xxxxx.us-east-1.es.amazonaws.com
```

Do not put credentials in the repository. The Runtime should use its IAM execution role.

## 4. Deploy

After bootstrap:

```bash
./scripts/deploy.sh
```

This runs:

```bash
agentcore deploy
agentcore status
```

Save the Runtime ARN returned by `agentcore status`.

## 5. Run an investigation

```bash
cd app/DBOpsAgent
uv sync
uv run client.py \
  --runtime arn:aws:bedrock-agentcore:us-east-1:ACCOUNT:runtime/RUNTIME_ID \
  --input 'Investigate elevated OpenSearch search latency for the configured domain. Do not make any changes. Gather evidence from OpenSearch and CloudWatch and produce an RCA with confidence.'
```

The client prints the session ID, command executions, tool calls, and final response.

## 6. Continue the investigation

```bash
uv run client.py \
  --runtime "$RUNTIME_ARN" \
  --session-id "$SESSION_ID" \
  --input 'Compare the current symptoms against the previous baseline and identify what evidence would falsify the current hypothesis.'
```

## 7. Local tests

```bash
python3 -m unittest discover -s tests -v
```

## Security model

The first release is intentionally read-only:

- no OpenSearch PUT/POST/DELETE APIs
- no RDS modification APIs
- no scaling APIs
- no shell access to destructive AWS commands
- no SQL execution
- only approved diagnostic scripts/tools

Tighten the `dbops-readonly-policy.json` resource ARNs before production use. The included wildcard permissions are for the initial POC and should be scoped to the approved account, Region, domains, log groups, and metric namespaces.
